# 15. NexArm + Sliding Rail Warehouse Sandbox

The **NexArm Sliding Rail Warehouse Sandbox Kit** is an intelligent sorting expansion kit that integrates a robotic arm, an electric sliding rail, and warehouse scenarios. It is equipped with core modules including the NexArm robotic arm, a 3D depth camera, an electric sliding rail, a metal baseplate for the sliding rail sandbox scene, a visual recognition panel measuring 264 × 264 mm, warehouse brackets, colored plastic trays, color cubes, waste/tag cards, and an optional WonderEcho Pro AI voice interaction box. It supports applications such as vision recognition, color block sorting, waste classification, tag sorting, robotic arm grasping, sliding rail transport, and placement across upper shelf, lower shelf, and 4-slot grid locations, making it suitable for studying multi-axis collaborative control, warehouse-style automated sorting, and ROS scenario development.

### 15.2.3 Robot Startup Instructions

This section covers the power-on status of the robot and functional verification of each module. After completion, proceed to subsequent chapters to learn app control.

To connect to the robot via remote tools, explore additional robot applications, and inspect programs, refer to [1. Tutorials / 1. NexArm User Manual / 1.5 Development Environment Setup and Configuration](https://wiki.hiwonder.com/projects/NexArm/en/ros-version/docs/1.%20NexArm%20User%20Manual.html#_1-5-development-environment-setup-and-configuration).

> [!NOTE]
>
> **The robotic arm must be secured firmly before starting. Sandbox kits must ensure the base screws are tightened. The robotic arm generates swing and inertia during startup and operation. If unsecured, it may tip over, fall, or sustain damage, and may also pose safety risks.**

1. Connect the 12 V 5 A power adapter to the ESP32 controller. Following this order ensures proper operation of all robotic arm hardware.

   <img class="common_img" src="../_static/media/chapter_1/section_3/media/image2.png" style="width:500px"  />

2. Do not stack robotic arms to prevent locked-rotor states upon power-on, which can damage the servos.

3. Do not operate the robotic arm under heavy loads for extended periods, as this will also shorten servo service life or cause permanent damage.

4. Maintain a safe distance from the robot before starting to prevent injury caused by accidental contact after power-on.

5. Push the power switch to the **ON** position.

<img class="common_img" src="../_static/media/chapter_1/section_3/media/image3.png" style="width:500px"  />

Wait approximately 1 minute. The robotic arm returns to its initial posture, and the buzzer emits a short beep, indicating that device startup is complete.

> [!NOTE]
>
> **If the buzzer does not emit a short beep, a hardware issue such as a buzzer malfunction may exist. This does not typically occur under normal usage. If this happens, contact customer support for assistance.**

* **Adjusting Color Thresholds**

1. Open the LAB Tool. In the color list of the recognition adjustment area, select the color requiring threshold adjustment, using red as an example here.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image21.png" style="width:300px"  />

2. Set the **min** values of the L, A, and B components to **0**, and set the **max** values to **255**.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image22.png" style="width:800px"  />

3. Place the colored object within the camera field of view. Refer to the LAB color space distribution diagram, and adjust the L, A, and B components toward the target color range.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image23.png" style="width:600px"  />

Red is located near **+a**, so increase the A component by keeping its **max** value unchanged and increasing its **min** value until the colored object area in the left image display turns white while other areas turn black.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image24.png" style="width:800px"  />

4. Adjust the remaining L and B components according to the operating environment. If the red color appears lighter, increase the **min** value of the L component. If it appears darker, decrease the **max** value of the L component. If the red color has a warmer tone, increase the **min** value of the B component. If it has a cooler tone, decrease the **max** value of the B component.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image25.png" style="width:700px"  />

The table below provides parameter reference information for LAB threshold adjustment:

| Color Component | Value Range | Corresponding Color Interval |
| :---: | :---: | :---: |
| L | 0-255 | Black-White (-L to +L) |
| A | 0-255 | Green-Red (-a to +a) |
| B | 0-255 | Blue-Yellow (-b to +b) |

5. Click **Save** in the recognition adjustment area to save the color threshold adjustment parameters.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image26.png" style="width:800px"  />

## 15.4 Scene Type Selection

NexArm expansion scenes are classified into several types: Scene 0 for the non-sandbox scene, Scene 1 for the basic sorting sandbox scene, Scene 2 for the standard sorting sandbox scene, Scene 3 for the advanced sorting sandbox scene, Scene 4 for the sliding rail warehouse sandbox scene, Scene 5 for the dual-arm conveyor sandbox scene, NexArm_mecanum for the Mecanum-wheel chassis, and NexArm_Track for the tank chassis. After installation, switch the device version according to the installed accessories before normal operation.

> [!NOTE]
>
> * **The robot factory default is the non-sandbox scene, which corresponds to Scene 0.**
> * **The robotic arm must be secured firmly before starting. Sandbox kits must ensure the base screws are tightened. The robotic arm generates swing and inertia during startup and operation. If unsecured, it may tip over, fall, or sustain damage, and may also pose safety risks.**

The detailed steps are as follows:

1. Power on the robotic arm and connect it to the remote control software **VNC**. Refer to [1. Tutorials / 1. NexArm User Manual / 1.5 Development Environment Setup and Configuration](https://wiki.hiwonder.com/projects/NexArm/en/ros-version/docs/1.%20NexArm%20User%20Manual.html#_1-5-development-environment-setup-and-configuration).

3. Select the appropriate scene option based on the robotic arm version and accessory type:

<img class="common_img" src="../_static/media/chapter_15/section_2/media/image2.png" style="width:800px"  />

Among them, **Scene 0** represents the non-sandbox scene, **Scene 1** represents the basic sorting sandbox scene, **Scene 2** represents the standard sorting sandbox scene, **Scene 3** represents the advanced sorting sandbox scene, **Scene 4** represents the sliding rail warehouse sandbox scene, and **Scene 5** represents the dual-arm conveyor sandbox scene.

4. Select **Scene 4**, representing the sliding rail warehouse sandbox scene.

<img class="common_img" src="../_static/media/chapter_15/section_2/media/image7.png" style="width:800px"  />

* **scene4_runtime.py File Analysis**

The Python file is located at: **~/ros2_ws/src/app/app/scene4_runtime.py**

This file contains the core shared logic for Scene 4, performing the following tasks:

1. Reading the active scene and YAML configuration.
2. Parsing the sliding rail parameters `rail` to obtain total steps, subdivision, observation positions, and placement positions.
3. Parsing `scene4_place` to determine whether the target should be placed in `frame`, `upper_shelf`, or `lower_shelf`.
4. Parsing `scene4_grid` to determine which slot index the target corresponds to.
5. Parsing `scene4_absolute_positions` to retrieve fixed coordinates for the frame, upper shelf, and lower shelf.
6. Parsing `scene4_shelf.rail_slots` to obtain the absolute sliding rail step counts corresponding to each shelf slot.
7. Calling the `/ros_robot_controller/stepper/set_position` service to control sliding rail movement.

(1) Determining Target Placement Destination

```python
def scene4_target_destination(scene_cfg, target_key, target_position=None):
    target_key = str(target_key)
    if target_key not in SCENE4_COLOR_KEYS:
        return None
    place = scene4_place_config(scene_cfg)
    destination = place["targets"].get(target_key, place["default_destination"])
    if destination in SCENE4_VALID_DESTINATIONS:
        return destination
    return SCENE4_PLACE_FRAME
```

This function reads `scene4_place.targets` in the YAML file. For example:

```yaml
scene4_place:
  default_destination: upper_shelf
  targets:
    red: upper_shelf
    green: upper_shelf
    yellow: upper_shelf
    blue: frame
```

This indicates that red, green, and yellow are placed on the upper shelf, while blue is placed in the frame area.

(2) Retrieving Fixed Placement Coordinates

```python
def scene4_fixed_place_position(scene_cfg, target_key):
    destination = scene4_target_destination(scene_cfg, target_key)
    if destination in SCENE4_SHELF_LEVELS:
        return scene4_shelf_fixed_position(scene_cfg, target_key, destination)
    if destination == SCENE4_PLACE_FRAME:
        return scene4_frame_slot_target(scene4_frame_slot_index(scene_cfg, target_key), scene_cfg)
    return None
```

If the target is to be placed on a shelf, the program identifies the corresponding slot based on `scene4_grid`, and retrieves `[x, y, z]` coordinates from `scene4_absolute_positions.upper_shelf_slots` or `scene4_absolute_positions.lower_shelf_slots`. If the target is to be placed in the frame, coordinates are retrieved from `scene4_absolute_positions.frame_slots`.

Therefore, the actual placement coordinates for red, green, yellow, and blue in Scene 4 are primarily determined by the following fields:

```yaml
scene4_absolute_positions:
  frame_slots:
  upper_shelf_slots:
  lower_shelf_slots:

scene4_grid:
  all_slots:
  all_upper_slots:
  all_lower_slots:
```

(3) Computing Shelf Placement Actions

```python
def scene4_shelf_place(scene_cfg, target_key, target_position):
    destination = scene4_target_destination(scene_cfg, target_key, target_position)
    shelf = scene4_shelf_config(scene_cfg)
    if destination not in shelf["levels"]:
        return None
    level = shelf["levels"][destination]
    result = {
        "destination": destination,
        "rail_position": scene4_shelf_rail_position(scene_cfg, target_key, target_position, destination),
        "pose": dict(level["pose"]),
        "target_position": [float(target_position[0]), float(target_position[1]), float(target_position[2])],
    }
    if "approach_pose" in level:
        result["approach_pose"] = dict(level["approach_pose"])
    return result
```

This function returns complete shelf placement information, including the target shelf level, sliding rail absolute position, robotic arm placement pose, and approach pose. Note the units used in the configuration:

| Configuration Field | Unit | Description |
| :--- | :--- | :--- |
| `scene4_absolute_positions` | Meters | For example, `0.24` represents 240 mm, recording the spatial coordinates of each slot. |
| `scene4_shelf.levels.*.pose` | Millimeters / Degrees | For example, `x: 348.0` represents 348 mm, representing the pose published when the robotic arm executes placement. |
| `scene4_shelf.rail_slots` | Steps | For example, `slot_1: 3900` represents the absolute position when the sliding rail moves to slot 1. |

(4) Controlling Sliding Rail Movement

```python
def move_scene4_rail_to_position(
    node,
    client,
    position,
    scene_path=None,
    logger=None,
    reset_first=False,
):
    scene_name, scene_cfg = load_active_scene(scene_path)
    if scene_name != SCENE4_ID:
        return True

    rail = scene4_rail_config(scene_cfg)
    if not rail["enabled"]:
        return True

    position = int(max(0, min(int(position), rail["total_steps"])))
    ok, message = call_stepper_position(
        node,
        client,
        position=position,
        reset_first=reset_first,
        subdivision=rail["subdivision"],
        reset_wait_sec=rail["reset_wait_sec"],
        speed_steps_per_sec=rail["speed_steps_per_sec"],
    )
    return ok
```

This function reads the `rail` configuration and invokes the stepper motor absolute positioning service. In the current YAML file:

```yaml
rail:
  enabled: true
  total_steps: 4200
  subdivision: 2
  calibration_abs_position: 4000
  place_abs_position: 700
```

In the program, `subdivision: 2` is converted into 4 microsteps. Therefore, the sliding rail positions for the shelf slots primarily depend on group `'4'` under `scene4_shelf.rail_slots`:

```yaml
scene4_shelf:
  rail_slots:
    '4':
      slot_1: 3900
      slot_2: 2967
      slot_3: 2033
      slot_4: 1100
```

If the lateral position of a shelf slot is inaccurate, modify the corresponding `slot_1`, `slot_2`, `slot_3`, or `slot_4` value.

* **object_sorting.py Execution Workflow**

The Python file is located at: **~/ros2_ws/src/app/app/object_sorting.py**

During color block sorting, the program first recognizes the target color block and computes grasping coordinates. After grasping completes, the Scene 4 placement logic is executed:

```python
position = self.resolve_place_position(target[0])
shelf_place = self._resolve_scene4_shelf_place(target[0], position)
if shelf_place is not None:
    self._execute_scene4_shelf_place(target[0], shelf_place)
    self._reset_tracking_state()
    continue
```

In this process, `resolve_place_position()` prioritizes calling `scene4_runtime.scene4_fixed_place_position()`:

```python
if scene_name == scene4_runtime.SCENE4_ID:
    fixed_position = scene4_runtime.scene4_fixed_place_position(scene_cfg, target_key)
    if fixed_position is not None:
        return scene_play_registry.apply_global_place_offset(
            fixed_position,
            self.scene_config_path,
        )
```

In Scene 4, placement positions for red, green, yellow, and blue are resolved first according to `scene4_place`, `scene4_grid`, and `scene4_absolute_positions`. If no valid position is obtained from these fields, the program falls back to the generic `place_targets`.

When a target must be placed on a shelf, `_execute_scene4_shelf_place()` performs the following sequence:

1. Move to a safe transition pose.
2. Call `move_scene4_rail_to_position()` to move the sliding rail to the absolute step count for the target slot.
3. If an approach pose is configured, move to `approach_pose` first.
4. Move to `scene4_shelf.levels.upper_shelf.pose` or `scene4_shelf.levels.lower_shelf.pose`.
5. Open the mechanical gripper to complete placement.
6. Return to the approach pose or safe transition pose.

* **Placement Parameter Modification Recommendations**

| Modification Goal | Primary Location to Inspect or Modify |
| :--- | :--- |
| Destination for a specific color: upper shelf, lower shelf, or frame | `scene4_place.targets` |
| Slot index assignment for a specific color | `scene4_grid.all_upper_slots`, `scene4_grid.all_lower_slots`, `scene4_grid.all_slots` |
| `[x, y, z]` coordinates for frame or shelf slots | `scene4_absolute_positions` |
| Lateral offset when sliding rail stops at a slot | `scene4_shelf.rail_slots.'4'.slot_1` to `slot_4` |
| Robotic arm pose error during shelf placement | `scene4_shelf.levels.upper_shelf.pose` or `scene4_shelf.levels.lower_shelf.pose` |
| Inappropriate observation pose | `scene4_pick.lower_board.view_pose` |

Therefore, `place_targets` serves as a generic fallback placement table. In Scene 4 shelf sorting, fixed slot placement for red, green, yellow, and blue is determined jointly by `scene4_place`, `scene4_grid`, `scene4_absolute_positions`, and `scene4_shelf`.
