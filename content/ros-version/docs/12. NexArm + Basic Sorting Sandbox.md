# 12. NexArm + Basic Sorting Sandbox

[TOC]

The **NexArm Basic Sorting Sandbox Kit** is an intelligent robotic arm sorting kit designed for introductory robot vision sorting and fundamental ROS development. It is equipped with the NexArm robotic arm, a 3D depth camera, a metal baseplate for the basic sorting sandbox scene, a scene recognition area panel measuring 176 × 160 mm, a 7-inch touch screen, color blocks, wooden blocks, waste/tag cards, and other modules, with an optional WonderEcho Pro AI voice interaction box. This kit supports various applications, including color threshold adjustment, camera calibration, pixel positioning, depth positioning, color block recognition, robotic arm grasping, and color-based sorting. It serves as an ideal baseline learning environment for robotic arm vision recognition and ROS sorting workflows.

### 12.2.3 Robot Startup Instructions

This section covers the power-on status of the robot and functional verification of each module. After completion, proceed to subsequent chapters to learn app control.

To connect to the robot via remote tools, explore additional robot applications, and inspect programs, refer to [1. Tutorials / 1. NexArm User Manual / 1.5 Development Environment Setup and Configuration](https://wiki.hiwonder.com/projects/NexArm/en/ros-version/docs/1.%20NexArm%20User%20Manual.html#_1-5-development-environment-setup-and-configuration).

> [!NOTE]
>
> **The robotic arm must be secured firmly before starting. Sandbox kits must ensure the base screws are tightened. The robotic arm generates swing and inertia during startup and operation. If unsecured, it may tip over, fall, or sustain damage, and may also pose safety risks.**

   <img class="common_img" src="../_static/media/chapter_1/section_3/media/image2.png" style="width:500px"  />

2. Do not stack robotic arms to prevent locked-rotor states upon power-on, which can damage the servos.

3. Do not operate the robotic arm under heavy loads for extended periods, as this will also shorten servo service life or cause permanent damage.

4. Maintain a safe distance from the robot before starting to prevent injury caused by accidental contact after power-on.

5. Push the power switch to the **ON** position.

<img class="common_img" src="../_static/media/chapter_1/section_3/media/image3.png" style="width:500px"  />

Wait approximately 1 minute. The robotic arm returns to its initial posture, and the **buzzer** emits a short beep, indicating that device startup is complete.

> [!NOTE]
>
> **If the buzzer does not emit a short beep, a hardware issue such as a buzzer malfunction may exist. This does not typically occur under normal usage. If this happens, contact customer support for assistance.**

* **Adjusting Color Thresholds**

1. Open the LAB Tool. In the color list of the recognition adjustment area, select the color requiring threshold adjustment, using red as an example here.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image21.png" style="width:300px"  />

2. Set the **min** values of the L, A, and B components to **0**, and set the **max** values to **255**.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image22.png" style="width:800px"  />

3. Place the colored object within the camera field of view. Refer to the LAB color space distribution diagram, and adjust the L, A, and B components toward the target color range.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image23.png" style="width:600px"  />

Red is located near **+a**, so increase the A component by keeping its **max** value unchanged and increasing its **min** value until the colored object area in the left image display turns white while other areas turn black.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image24.png" style="width:800px"  />

4. Adjust the remaining L and B components according to the operating environment. If the red color appears lighter, increase the **min** value of the L component. If it appears darker, decrease the **max** value of the L component. If the red color has a warmer tone, increase the **min** value of the B component. If it has a cooler tone, decrease the **max** value of the B component.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image25.png" style="width:700px"  />

The table below provides parameter reference information for LAB threshold adjustment:

| Color Component | Value Range | Corresponding Color Interval |
| :---: | :---: | :---: |
| L | 0-255 | Black-White (-L to +L) |
| A | 0-255 | Green-Red (-a to +a) |
| B | 0-255 | Blue-Yellow (-b to +b) |

5. Click **Save** in the recognition adjustment area to save the color threshold adjustment parameters.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image26.png" style="width:800px"  />

* **Adding New Recognizable Color**

In addition to the built-in recognizable colors, additional colors can be added. Taking yellow as an example, the specific operating steps are as follows:

1. Open the LAB Tool and click **Add**.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image27.png" style="width:200px" />

2. Enter the color name in the **name** field and click **OK**.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image28.png" style="width:400px"  />

3. Select the newly added color from the color list.

<img  class="common_img" src="../_static/media/chapter_1/section_5/media/image29.png" style="width:200px" />

4. Place the colored object within the camera field of view, and drag the L, A, and B component sliders to adjust thresholds until the colored object area in the left image display turns white while other areas turn black.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image30.png" style="width:800px"  />

5. Click **Save** in the recognition adjustment area to save the color threshold adjustment parameters.

<img class="common_img" src="../_static/media/chapter_1/section_5/media/image31.png" style="width:800px"  />

After completing color threshold adjustments, click **Quit** to exit the interface.

### 12.5.3 Pixel Positioning

> [!NOTE]
>
> **The calibration option shown in the illustration is scene_3 for the advanced sorting sandbox. The equipment used in this tutorial is scene_1 for the basic sorting sandbox scene. The calibration operating steps are identical and can be executed following this workflow.**

1. Select **Pixel Positioning** in **Mode**, and place the color block at the center position.

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image4.png" style="width:800px"  />

2. Click the color block in the color calibration area with the mouse. The robotic arm automatically samples the color, recognizes the target, and executes only the grasping motion. Adjust the positioning offsets for X, Y, and Z based on the grasping results. Note that **Save** must be clicked after modifying values for changes to take effect.

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image5.png" style="width:800px"  />

   As shown in the figure above, adjusting the X-axis value moves the robotic arm forward or backward. For example, setting X to a positive value moves the arm forward.
   Adjusting the Y-axis value moves the robotic arm left or right. For example, setting Y to a positive value moves the arm to the left.
   Adjusting the Z-axis value moves the robotic arm up or down. For example, setting Z to a positive value moves the arm upward.

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image6.png" style="width:800px"  />

3. After adjusting the parameters, click **Save** first to save and apply the configured data to the robotic arm grasping program. Next, click **Home** to return to the robotic arm recognition and grasping state. Finally, click the color block again with the mouse. The robotic arm automatically samples the color, identifies the position, and performs grasping.

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image7.png" style="width:800px"  />

4. Once the color block can be successfully grasped at the center position, place the wooden block within the bounding box on the map. Click the color block with the mouse, and adjust the positioning Y **Scale** according to the grasping performance of the mechanical gripper. This parameter adjusts the gripper opening size along the Y-axis. Once the center block offset is properly calibrated, only the scale needs adjustment. Ensure that all four corners of the bounding box can be grasped normally.

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image8.png" style="width:800px"  />

   <img class="common_img" src="../_static/media/chapter_17/section_2/media/image10.png" style="width:800px"  />

* **object_sorting.py Execution Workflow**

The Python file is located at: **~/ros2_ws/src/app/app/object_sorting.py**

During color block sorting, the program first recognizes target color blocks, and then executes grasping and placement within the `transport_thread()` thread. The core workflow is as follows:

1. Obtain grasp coordinates, rotation angles, and target colors from visual recognition results.
2. Apply robotic arm calibration corrections to the grasp coordinates using `calibrated_pose.apply_axis_calibration()`.
3. Call `pick_and_place.pick()` to grasp the color block.
4. Call `resolve_place_position()` to retrieve placement coordinates according to the target color.
5. Parse `place_pitch` and `place_roll`, and apply kinematic calibration to correct placement coordinates.
6. Call `pick_and_place.place()` to complete placement.

The key function for acquiring placement coordinates is as follows:

```python
def resolve_place_position(self, target_key):
    scene_name, scene_cfg = self._load_active_scene_config()

    place_targets = scene_cfg.get('place_targets', {}) if isinstance(scene_cfg.get('place_targets'), dict) else {}
    raw = place_targets.get(target_key, self.place_position.get(target_key, DEFAULT_SCENE_PLACE_TARGETS.get(target_key)))
    if raw is None:
        return None

    pos = [float(raw[0]), float(raw[1]), float(raw[2])]

    policy = DEFAULT_PLACE_POLICY.copy()
    if isinstance(scene_cfg.get('place_policy'), dict):
        policy.update(scene_cfg['place_policy'])
    if bool(policy.get('only_left_y_positive', False)) and pos[1] < 0.0:
        pos[1] = abs(pos[1])
    min_place_z = float(policy.get('min_place_z', DEFAULT_PLACE_POLICY['min_place_z']))
    if pos[2] < min_place_z:
        pos[2] = min_place_z

    return scene_play_registry.apply_global_place_offset(pos, self.scene_config_path)
```

In Scene 1, actual placement coordinates for red, green, and blue color blocks are preferentially retrieved from `place_targets` in **scene1_calibration.yaml**. If the target is not defined in the YAML file, default coordinates configured in the program are used.

The code related to placement actions is as follows:

```python
position = self.resolve_place_position(target[0])
cfg_roll = self.resolve_place_roll(target[0])
yaw = float(cfg_roll) if cfg_roll is not None else self.calculate_place_grasp_yaw(position, 0)
place_pitch = self.resolve_place_pitch(target[0], 80.0)

finish = pick_and_place.place(position, place_pitch, yaw, 200, self.arm_pub, **place_kwargs)
```

Therefore, if color block placement is inaccurate, modify `place_targets.red`, `place_targets.green`, and `place_targets.blue` first. If the placement angle is inappropriate, add or modify `place_pitch` and `place_roll`.


Scene 1 also includes two dedicated action functions for waste classification. During grasping, `scene1_pick_hold_yaw()` is invoked to maintain the current gripper angle after grasping:

```python

    finish = pick_and_place.pick(position, 90, yaw, 470, 0.02, self.arm_pub, None,
```

`scene1_direct_place()` converts coordinates in meters from the YAML file into millimeters before publishing the robotic arm posture:

```python

z_mm = float(position[2]) * 1000.0

roll_deg = float(roll)

```

Therefore, when waste classification placement is inaccurate, modify the `[x, y, z]` coordinates corresponding to `residual_waste`, `food_waste`, `hazardous_waste`, and `recyclable_waste` in **scene1_calibration.yaml**.

* **Placement Parameter Modification Recommendations**

| Symptom to Adjust | Preferred Configuration to Modify |
| :--- | :--- |
| Inaccurate placement for red, green, or blue color blocks | `place_targets.red`, `place_targets.green`, `place_targets.blue` in **scene1_calibration.yaml** |
| Inaccurate placement for yellow color blocks | Add or modify `yellow` under `place_targets` |
| Inaccurate placement for specific waste categories | `place_targets.residual_waste`, `place_targets.food_waste`, `place_targets.hazardous_waste`, `place_targets.recyclable_waste` |
| Placement position along left-right axis not as expected | Check `place_policy.only_left_y_positive`. When set to `true`, negative `y` automatically converts to positive `y` |
| Placement height too high or too low | Modify the third coordinate value `z` for the target, noting the minimum height limit enforced by `min_place_z` |
| Gripper angle unsuitable during placement | Add or modify `place_pitch` and `place_roll` |
| Global offset across all targets | Check camera/robotic arm calibration first, along with `kinematics.offset` and `kinematics.scale` |

In summary, the core configuration for the Scene 1 basic sorting sandbox resides in `place_targets` within **scene1_calibration.yaml**. The program automatically selects corresponding coordinates based on the currently recognized target name to execute placement.
